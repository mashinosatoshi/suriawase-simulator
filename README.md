# すり合わせシミュレーター

AI と 1 ターンずつチャットで対話し、相手が抱える課題を**すり合わせて解消していく**ターン制の対話ゲーム。
勝ち負けではなく、「相手の本音を聞き出し、お互いが納得できる形に落とし込めたか」が成否になる。

- シナリオ (舞台・登場人物・隠された懸念) は **AI がその場で生成**する。
- AI は **Claude / GPT / Gemini** のどれか (各社の API キーがあれば動く)。ブラウザはチャット + 懸念ボード。
- ゲームは**ブラウザの中だけで動く**。AI の会社の API をブラウザから直接呼ぶので、API キーは運営のサーバーを通らない。公開用のサーバーは画面のファイルを配るだけ。

お問い合わせ・不具合の報告は [Issues](https://github.com/mashinosatoshi/suriawase-simulator/issues) へ (公開されるので、個人情報や API キーは書かないでください)。脆弱性は [SECURITY.md](SECURITY.md) の方法で非公開でお知らせください。

## 遊び方 (API キーで遊ぶ)

1. 初回だけ `git clone https://github.com/mashinosatoshi/suriawase-simulator.git` → `npm install`。
2. `npm start`。ブラウザが自動で開く (開かなければ http://localhost:3100)。最初に、題名・ゲームの概要・遊び方・GitHub などのリンクを載せた紹介画面が出る。「ゲームを始める」を押すと次に進む。
3. 「AI の設定」画面で **AI サービス**を選び、**API キー**を貼り付けて「決定」。キーが使えると確かめられたら、**モデル**を選んで「確定」。
4. 「どんな話にしますか？」画面で、話題 (空欄なら、ゲームがランダムに選んだ現代のお題で作る) と**難易度** (簡単・普通・難しい・ランダム) を選んで「はじめる」。AI がシナリオを作り、対話が始まる。

AI を確定した後の新しいシナリオは 4 から始まる (「変更」で 3 に戻れる)。
対話の途中でも、画面上の「AI を変更」で AI (サービス・モデル) を変えられる。次の返答から新しい AI が、それまでの会話と本音の進み具合を引き継いで相手役を続ける。

- API キーの発行先: Claude は Claude Console、GPT は OpenAI Platform、Gemini は Google AI Studio (開始画面にリンクが出る)。
- 「決定」では、料金のかからない呼び出し (Claude はトークン数の計算、GPT と Gemini はモデル一覧の取得) でキーを確かめる。間違ったキーはその場で知らせる。
- 入力したキーは**このページのメモリにだけ**置き、AI の会社 (`api.anthropic.com` / `api.openai.com` / `generativelanguage.googleapis.com`) へ直接送る。ゲームのサーバーには送らず、どこにも保存しない。ページを閉じるか「消す」を押すと消える。
- 対話もこのページの中だけにある。対話中にページを閉じたり再読み込みしたりすると消える (その前に確認が出る)。
- キーは開始画面で入力したものだけを使う。`.env` や環境変数からは読まない。
- 遊ぶたびに、選んだ会社の API 料金がかかる。目安は 1 ゲーム (20 ターン前後) で、Claude Opus 5.5 なら 1 ドル前後 (概算)。
- 混雑 (503 など)・利用上限 (429)・通信の乱れのような一時的な失敗は、約 4・10・25 秒待って自動で再試行する (画面に案内が出る)。それでも直らなければ止まる。キーが無効などは、待たずにすぐ止まる。止まったら、画面に理由と「再試行」が出る。1 つの返答につき 4 回まで試して止まるので、際限なく課金されることはない。会話中なら「AI を変更」で別の AI に切り替えて続けることもできる。

| 提供元 | モデル (開始画面の選択肢) | API |
|---|---|---|
| Claude | `claude-opus-5-5` (既定) / `claude-sonnet-5-5` / `claude-haiku-5-5` | Messages API。拒否時のフォールバック (`fallbacks: "default"`) とプロンプトキャッシュあり |
| GPT | `gpt-6-astra` (既定) / `gpt-6.1-sol` / `gpt-6.1-terra` / `gpt-6-luna` | Responses API (GPT-6 系のツール呼び出しはこちらのみ)。会話は OpenAI に保存しない (`store: false`) |
| Gemini | `gemini-3.5-flash-lite` (既定) / `gemini-3.8-flash` / `gemini-4-argon` | generateContent。無料枠で 1 ゲームを無理なく遊べるのは Flash-Lite (3.8 Flash は 1 日の回数が少なく、4 Argon は有料枠のみ) |

一覧に無いモデルも「その他」でモデル ID を入力すれば使える。モデル一覧は [src/llm/catalog.ts](src/llm/catalog.ts)。

## 遊び方 (Claude Code で遊ぶ)

API キーの代わりに、Claude Code に GM を務めてもらうこともできる (MCP)。

1. Claude Code をこのフォルダで起動し、`.mcp.json` の `suriawase-simulator` を承認する。
2. ブラウザで http://localhost:3100 を開く (MCP サーバーの起動と同時に配信される。`public/client.js` が無ければ先に `npm run build:client`)。
   この版だけは、ゲームの状態をローカルのサーバーが持ち、ページはそのサーバーと通信する (サーバーが配信したページに印が付く)。
3. Claude に頼む: 「suriawase-simulator の GM になって。wait_for_player_turn のループで進めて。」

### ゲームの流れ

プレイヤーは**自由な会話文を 1 ターンに 1 回**送る。行動の種類 (質問・提案など) は選ばない。
質問なのか共感なのか提案なのかは、AI が文面から汲み取る。

- 宛先 (「全員」か特定の人) は選べる。宛先は相手へのヒントで、他の人が割り込むこともある。
- 入力欄の下の「締める」ボタンで、いつでも対話を終えられる (これだけがコマンド)。

相手には隠れた**懸念**がある。**懸念ボードは空から始まり**、本音が見つかった分だけ増えていく
(未発見の懸念は、数も分類もブラウザには一切送られない)。会話ログには、会話と地の文だけが残る。

```
(未発見) → 未解決 → 検討中 → 解消
          (本音が出る) (案が出る) (条件を満たす)
```

- 本音は、聞き方がよくて相手の**信頼度**が足りているときだけ出る。押しつけると出てこない。
  信頼度は現実の対話と同じく数値では見えず、相手の表情 (気分) や口調の変化でだけ伝わる。
- 具体的な対処案や条件を出すと、懸念が「検討中」に進む。AI は、あなたの発言から**提案にあたる部分を一字一句そのまま引用**する必要があり、エンジンが発言と照合する (発言に無い提案は通らない)。
- 本音が見えている懸念なら、案が解消条件を満たし、相手がその場で納得すれば、検討中を挟まず**その場で解消**する (即決)。ただし**譲れない本音は即決しない**。相手が一度「本当に大丈夫か」と確かめてくるので、それに答えると解消する。
- 毎回こちらから形式的な案を出さなくてもよい。本音が見えた懸念について話を重ね、条件がそろうと、**相手の側から「私はこうしたい」と歩み寄ってくれる**。受け入れれば解消する。
- 解消には、開始時に固定された解消条件を満たす必要がある。足りなければ差し戻される。
- ターン数に上限がある。全部解消すれば「完全合意」、半分以上なら「妥協案」、それ以外は「持ち帰り」。
- 終了後は、見つけられなかった懸念も公開され、「会話を書き出す」で、会話の全文・結果・スコアの内訳・合意事項と持ち越し・振り返りを、1 つのテキストとしてコピーできる。
- 終了後に AI が**振り返り**を書く。総評、良かった点、次に活かせること、解消できなかった懸念ごとの助言 (どう聞けば本音が出たか)。

### 難易度

難易度はパラメータの組。開始画面の難易度の下にある「▶ パラメータ」を開くと、その場で中身を見て微調整できる (調整したら「普通 (調整あり)」のように表示される)。

| パラメータ | 簡単 | 普通 | 難しい | 確かめ方 |
|---|---|---|---|---|
| 懸念の数 | 4 | 5 | 7 | エンジン |
| 最初から話せる本音の数 | 2 | 2 | 1 | エンジン (`min_trust` が初期の信頼度以下の懸念がちょうどこの数) |
| 懸念 1 つあたりのターン数 (→ 上限) | 4 (20) | 3 (19) | 2 (18) | エンジン (上限 = 懸念の数 × これ + 4) |
| 最初の信頼度 (険悪度) | 3 好意的 | 2 様子見 | 0 不信感 | エンジン。冒頭の台詞と気分もこれに合わせる |
| 物わかり | よい | ふつう | わるい | AI への指示 (提案の受け取り方・解消の判定の厳しさ) |
| 歩み寄りに要るターン数 | 1 | 2 | 3 | エンジン |
| 歩み寄りに要る信頼度 | 2 | 3 | 4 | エンジン (その本音の `min_trust` + 1 のほうが高ければそちら) |
| 歩み寄りの間隔 | 1 | 2 | 3 | エンジン (このターン数に 1 回まで) |

初期値と範囲は [src/shared.ts](src/shared.ts) の `DIFFICULTY_PRESETS` / `PARAM_SPECS`、AI への指示の文面は [src/difficulty.ts](src/difficulty.ts)。
未発見の懸念は数も見せない方針なので、難易度の説明には懸念の数を出さない (見たい人だけが「パラメータ」を開いて見る)。

## シナリオの保存と読み込み (リサイクル)

遊んだシナリオを、ファイルに保存して、別の人が同じシナリオで遊べる。

- **書き出し:** シナリオを遊び始めてから、終わった後まで、いつでも「シナリオを書き出す」(ヘッダーと終了画面) でファイルに保存できる。ページを閉じる (画面を消す) と、シナリオは消える。ファイル名には、書き出した日時が付く (例: `すり合わせ-駅前の書店-20261105-152800.json`)。
- **読み込み:** 開始画面 (「どんな話にしますか？」) の「シナリオを読み込む…」でファイルを選ぶと、そのシナリオで最初から始まる。難易度とパラメータも、ファイルに書かれていたもの。シナリオを AI に作らせる手間は要らない (遊ぶのには AI が要る)。
- **プレイの結果とは切り離す:** ファイルに入るのは、シナリオそのもの (隠れた本音・解消条件などを含む) と、作られたときの難易度・パラメータだけ。会話・信頼度・本音の進み具合・結果・スコアは入らない。
- **暗号化:** ファイルは AES-256-GCM で暗号化される。遊んでいる最中に書き出しても、エディタで開いたときに隠れた本音が見えない (ネタバレにならない)。書き換えられたファイルは、復号のときに見つかって弾かれる。暗号化は画面 ([src/scenario-crypto.ts](src/scenario-crypto.ts)) だけで行い、ゲームの本体とサーバーは暗号化を知らない。
  - **標準のキー (ふつうはこちら):** 書き出すときの「キー」の欄を空欄のまま保存すると、アプリに組み込んだ標準のキーを使う。読み込む側も、キーの入力は要らない。**ソースコードは公開されているので、ソースを読んだ人から内容を完全に秘密にするものではない** (ネタバレの防止と、書き換えの検出が目的)。
  - **自分で決めたキー (必要なときだけ):** 書き出すときに「キー」の欄へ入力すると、そのキーから鍵を作って (PBKDF2-SHA256・60 万回) 暗号化する。読み込む人も、同じキーを知っている必要があり、ファイルを選ぶとキーを聞かれる。キーはファイルにも画面の外にも残らず、忘れると読み込めない。全角と半角 (`ＡＢＣ` と `ABC`)・前後の空白は区別しないが、大文字と小文字は区別する。長さは 100 文字まで。短い・推測されやすいキーは、ファイルを手に入れた人に総当たりで破られうる。ほかのサービスのパスワードは使わないこと。
- **読み込むときの検査:** 知らない人が作ったファイルでも、AI が作ったシナリオと同じ検査 (形・数・誘導や URL・キーらしい文字列。[src/scenario-file.ts](src/scenario-file.ts)) に通す。通らなければ、何も変えずに理由を出す。大きさにも上限がある。暗号化していない JSON も読み込める (自分で書いたシナリオなど)。

暗号化する前のファイルの形 (JSON):

```json
{
  "format": "suriawase-simulator/scenario",
  "version": 1,
  "difficulty": "normal",
  "params": { "concerns": 5, "openAtStart": 2, "nonNegotiable": 1, "trustStart": 5, "openness": 5, "turnsPerConcern": 3, "understanding": 5, "initiativeTurns": 2, "initiativeTrust": 7, "initiativeCooldown": 2 },
  "scenario": { "title": "…", "premise": "…", "characters": [], "concerns": [], "briefing": [], "opening": [] }
}
```

`scenario` の中身は [src/scenario.ts](src/scenario.ts) のシナリオのスキーマ、`params` は [src/shared.ts](src/shared.ts) の `DifficultyParams` (すべての項目が必須)。
暗号化したファイルは `{ "format": "suriawase-simulator/scenario-encrypted", "version": 1, "algorithm": "AES-256-GCM", "iv": "…", "data": "…" }` の形になる。自分で決めたキーのファイルには、鍵の作り方を示す `"kdf": { "name": "PBKDF2-SHA256", "iterations": 600000, "salt": "…" }` が加わる (これがあるファイルは、読み込むときにキーを聞かれる。キーそのものは入らない)。
MCP 版 (Claude Code が GM) でも、同じ画面から書き出し・読み込みができる (サーバーの `/api/export`・`/api/import`)。

## 公開する (Google Cloud Run)

ゲームはブラウザの中だけで動くので、公開用のサーバーは画面のファイルを配るだけ。

- [Dockerfile](Dockerfile) が画面をビルドし、`public/` を配信する小さなサーバー ([src/serve.ts](src/serve.ts) / [src/static.ts](src/static.ts)) と一緒にコンテナに詰める。サーバーは [public/_headers](public/_headers) のセキュリティヘッダーを付け、圧縮して返す。API は無く、キーも会話も通らない。コンテナは root では動かさない。
- デプロイの例: `gcloud run deploy suriawase-simulator --source . --region asia-northeast1 --allow-unauthenticated`
- 手元で公開用と同じ配信を試す: `npm run serve` (http://localhost:8080)。コンテナごと試すなら `docker build -t suriawase-simulator .` → `docker run --rm -p 8080:8080 suriawase-simulator`
- `public/_headers` は Cloudflare Pages / Netlify と同じ書式なので、そちらに置く場合もそのまま効く。CSP は `index.html` の meta にも書いてある (`frame-ancestors` は meta では効かないので、ヘッダーだけ)。
- **公開前に** `privacy.html` と `terms.html` の `〔公開日〕` を記入する (画面では黄色で目立つようにしてある)。
- アクセスのログは、運営者の Google Cloud プロジェクトの Cloud Logging に 30 日残る (既定の保存期間。プライバシーポリシーに記載している。保存期間を変えたら、ポリシーも直す)。
- GitHub の設定で「Private vulnerability reporting」を有効にしておく ([SECURITY.md](SECURITY.md) の報告先)。

## キーと安全のための仕組み

- **キーは運営のサーバーを通らない**: ブラウザから AI の会社へ直接送る。開始画面にも送り先を表示している。開発者ツールの「ネットワーク」で、通信先が AI の会社とこのサイトの画面ファイルだけであることを確かめられる。
- **キーはどこにも保存しない**: このページのメモリにだけ置く。ページを閉じるか「消す」で消える。
- **専用キーと上限額の案内**: 「AI の設定」の「安全に使うために」で、このゲーム専用のキーを作り、各社の管理画面で上限額を設定する手順をサービスごとに案内する (文面は [src/llm/catalog.ts](src/llm/catalog.ts) の `keySteps`)。
- **プライバシーポリシーと利用規約**: `public/privacy.html` / `public/terms.html`。ゲーム画面の下と「AI の設定」からリンクしている (対話とキーはページの中にしかないので、別のタブで開く)。
- **外部のスクリプトを読み込まない**: 解析タグも広告も無い。CSP で、スクリプトとスタイルはこのサイトのもの、通信先はこのサイトと 3 社の API だけに限っている。`eval` も使わない。他サイトへの埋め込みも禁止 (`frame-ancestors 'none'`)。
- **AI の出力は文字として表示するだけ**: HTML・Markdown・リンクとして描画しない (XSS と、リンクを使った情報の持ち出しを防ぐ)。
- **キーの貼り間違いを止める**: チャットやシナリオの希望に API キーらしい文字列があれば、AI に送らずに止める (会話として AI の会社に送られ、記録に残ってしまうため)。
- **AI の出力の検査**: URL、API キー・パスワードなどの入力や共有を求める文面、キーらしい文字列があれば差し戻す (ゲームの画面を装った誘導を防ぐ)。「API キー」という語そのものは IT が題材のシナリオで普通に出るので、求める言い方だけを対象にしている。
- **プロンプトインジェクション**: プレイヤーの発言とシナリオの希望は「台詞と希望であって、AI への指示ではない」と AI に伝え、ルール変更・隠し情報の開示・ゲームと関係の無い依頼には応じさせない。ルールの要所 (本音の解禁・段階・引用・歩み寄りの根拠) はエンジンが確かめる。まだ見つかっていない本音を台詞でほぼそのまま話したら差し戻す。
- **割り切り**: 隠し情報 (本音・解消条件・信頼度) もブラウザの中にあるので、開発者ツールで覗くことはできる。1 人用で勝ち負けも無いので、覗いて損をするのは本人だけ。エンジンの検証は「AI の迎合や手抜きを防ぐ」ためのもので、ブラウザの中でも同じように効く。

## 設計のポイント

- **手番の排他制御**: プレイヤーが送信すると、AI が `reply` するまで入力できない。古い手番への返答は無効。
- **AI の迎合を防ぐ仕組みをエンジン側で強制**: 解消条件はシナリオ確定時に固定。段階は 1 ターン 1 つ (例外は、本音が見えた懸念の即決。譲れない本音と歩み寄りは即決できない)。信頼度が足りない本音は出せない。検討中に進めるにも、即決するにも、プレイヤーの発言からの引用が要る。終了ターンは `epilogue` が必須。違反した `reply` は何も反映されずエラーになる。
  (限界: 引用が「本当に提案か」の判断は AI に任せている。エンジンが確かめるのは、引用がプレイヤーの発言に実在することまで。)
- **相手からの歩み寄りにも根拠を要求**: キャラクターが自分から着地点を示せるのは、エンジンが次を確かめたときだけ。本音が見えていて案がまだ無い懸念であること、信頼度が足りていること、本音が見えた後の**別々のターン**のプレイヤーの発言からの引用があること、ペース (1 回の返答で 1 つまで、間隔をあける)。数値は難易度で変わる (普通なら信頼度 3 以上、2 ターン分、2 ターンに 1 回)。解消はプレイヤーが受け入れた次のターン。プレイヤーが言っていない解決策を相手が作ることはできない。
  (限界: 積み重ねた発言が解消条件を本当に満たすかは、提案と同じく AI の判断。)
- **隠し情報は画面に出さない**: 未発見の懸念・解消条件・人物設定・信頼度は、エンジンと AI だけが使い、画面の状態 (`publicState`) には入れない。信頼度が動いたターンは、気分 (moods) の更新が必須 (プレイヤーへの唯一の手がかり)。
- **誘導しない**: 「何か言いかけて口をつぐんだ」「（うつむく）」のように、仕草で隠し事を匂わせる描写は禁止。エンジンがよくある言い回しを検出して `reply` を差し戻す (網羅はできないので、原則は AI への指示で伝えている)。気分は絵文字と感情の名前だけで伝える。
- **口調を保つ**: キャラクターごとに口調の決まり (`speech`) と手本のセリフ (`sample_lines`) をシナリオに持たせ、毎ターン AI に渡す。日本語の自然さそのものはエンジンでは検査できないので、指示と手本で支える。
- **進行の要約は出さない**: 「本音が見えた」「信頼度が上がった」のような説明行はチャットに出さない。現実の対話では見えないものだから。
- **仕事は状態から導出**: `wait_for_player_turn` は処理が終わるまで同じ仕事を返し続けるので、AI がコンテキストを失っても詰まらない。
- **内蔵 GM と MCP で同じルール**: ブラウザの中で API キーを使って動く内蔵 GM ([src/gm.ts](src/gm.ts)) も、MCP 経由の Claude Code も、同じツール定義 ([src/tools.ts](src/tools.ts)) と同じ指示 ([src/instructions.ts](src/instructions.ts)) を使い、検証はすべてエンジンが行う。内蔵 GM は検証エラーを AI に返して直させ、1 つの仕事につき 4 回まで試す。仕事ごとに必要なツールだけを渡す (新しいゲームは start_scenario、手番は reply、振り返りは submit_review)。
- **各社の会話履歴はそのまま返す**: Claude の thinking ブロック、OpenAI の推論アイテム、Gemini の thought signature は、受け取ったまま次の要求に含める (各社の API がそれを求めるため)。会話は追記だけ。
- **履歴は 8 手番で区切る**: 履歴を持ち越し続けると、毎回の要求が手番ごとに大きくなる (50 手番で約 10 万トークン。遅くなり、利用上限にも当たりやすい)。内蔵 GM は、プレイヤーの手番が 8 回続いたら会話を作り直し、いまの全状態 (隠し情報つき)・直近の会話・プレイヤーのこれまでの全発言を最初に渡して引き継ぐ。エンジンが状態を持っているので、AI の会話履歴が無くても続けられる。
- **「最初から」は AI 不要**: オープニングはシナリオに含まれるので、同じシナリオでの再挑戦は AI の手を借りずに始まる。

## MCP ツール

| ツール | 役割 |
|---|---|
| `wait_for_player_turn` | プレイヤーの発言 / 新規ゲームの依頼 / 終了後の振り返りの依頼が来るまで待つ (基本ループ) |
| `start_scenario` | シナリオを検証して採用し、ゲームを始める |
| `reply` | 1 ターン分の返答 (発言・信頼度・懸念の進行・気分) をまとめて返す |
| `submit_review` | 終了後の振り返りを提出する (解消できなかった懸念すべてに助言が要る) |
| `get_state` | 隠し情報を含む全状態 (復帰用) |

シナリオのスキーマは [src/scenario.ts](src/scenario.ts)、ルールは [src/engine.ts](src/engine.ts)、AI への指示は [src/instructions.ts](src/instructions.ts) を参照。

## 開発

```
npm install
npm test            # エンジン・内蔵 GM・ブラウザ版の本体・各社の接続部のテスト (実際の API は呼ばない)
npm run smoke       # 実サーバー + MCP クライアントで 1 ゲーム通す
npm run typecheck
npm run serve       # 公開用と同じ配信を手元で (http://localhost:8080)
```

ポートは `PORT` で変えられる (既定 3100)。`OPEN_BROWSER=0` で起動時にブラウザを開かない。

### 自動試遊 (会話の不自然さの洗い出し)

本物の AI に GM とプレイヤー役を任せて何ゲームも回し、登場人物の不自然な言動を審査役の AI に種類つきで挙げさせる。AI を呼ぶたびに課金されるので、少ない回数から始める。

```
npm run playtest -- --dry-run          # 作り物の AI で仕組みだけ確かめる (費用ゼロ)
npm run playtest -- --games 3          # 既定: GM・プレイヤー役は Claude Haiku 5.5、審査役は Sonnet 5.5 (effort medium)
npm run playtest -- --games 3 --judge anthropic:claude-haiku-5-5:medium    # 審査役も軽いモデルに
```

Claude Code では `/playtest [ゲーム数] [難易度] [GM] [プレイヤー役] [審査役]` でも回せる。各役は `haiku` / `sonnet` / `opus` (Claude Code のサブエージェント。API キー不要の MCP 版で動く) か、`gemini:gemini-3.5-flash-lite` のような `<提供元>:<モデル>` (各社の API) で指定する。例: `/playtest 3 normal gemini:gemini-3.5-flash-lite` (GM とプレイヤー役は Gemini、審査は Claude Code の Sonnet)。

- API キーは、起動するとブラウザに開く入力画面で受け取る (ファイルや環境変数からは読まない。メモリにだけ置く)。
- 結果は `playtest-results/<日時>/` に書き出す。`report.md` がまとめ (不自然さの種類ごとの件数・実例・使用量)、`game-NN.md` がゲームごとの会話と指摘。
- `--seed` が同じなら、同じお題・性格・難易度で回る。指示文やルールを直す前と後で同じ条件を回し、指摘の件数を比べる。
- ターンは既定で、偶数番目のゲームは上限まで使い (プレイヤー役は自分から締めない)、奇数番目は 4〜10 回目のどこかで締める (`--max-turns full` で常に上限まで、`--max-turns 10` で常に 10 回で締める)。
- 無料枠の 1 分あたりの上限に当たらないよう、Gemini は既定で 1 分 14 回・225,000 トークンまでに呼び出しを抑える (超えそうなら待つ。`--rpm`・`--tpm` で変えられる)。それでも上限 (429) に当たったら、少し待ってから続ける。
- そのほかの引数 (`--difficulty`・`--player`・`--judge none`・`--rpm`・`--tpm`・`--out`) は [scripts/playtest/config.ts](scripts/playtest/config.ts) を参照。
